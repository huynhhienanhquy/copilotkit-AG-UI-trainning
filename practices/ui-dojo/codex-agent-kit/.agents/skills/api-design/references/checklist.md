# api-design checklist

- [ ] Resource and use case identified
- [ ] HTTP method and path are correct and consistent
- [ ] Request schema defined with types, required fields, and constraints
- [ ] Response schema defined with consistent structure
- [ ] Status codes documented for each outcome
- [ ] Error format consistent with existing API error contract
- [ ] Naming follows REST conventions (plural nouns, lowercase, hyphens)
- [ ] Pagination, filtering, sorting considered for list endpoints
- [ ] Authorization boundaries defined per endpoint
- [ ] Versioning strategy determined if breaking change
- [ ] Examples provided for success and error paths
- [ ] Backward compatibility assessed
- [ ] Consumer impact documented
